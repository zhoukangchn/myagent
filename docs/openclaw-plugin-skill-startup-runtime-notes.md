# Plugin / Skill：启动时 vs 运行时（口径备忘 / 讲解稿）

## 核心抓手：只抓两个时刻
- **启动时（startup）**：把能力“装进系统”，让系统能识别/配置/治理。
- **运行时（runtime）**：一次调用真正发生的地方，决定稳定性与可观测性。

---

## 三句口径（最好用）
1) **Plugin = 能力 + 执行**（启动时加载注册；运行时承接调用干活）
2) **Skill = 方法 + 流程**（塞进提示词，教模型怎么用能力、怎么兜底、怎么输出）
3) **Tool call = 按按钮**（模型在运行时发起结构化调用）

---

## 你要讲的内部模型例子（Provider 方式）
### 启动时要点（领导最关心“为什么必须 plugin”）
- 用 plugin 把内部模型接入成系统级 provider/auth：启动时加载、初始化鉴权/客户端/路由/观测，并注册成系统认可的模型入口。
- 结果：内部模型不是“某次会话里跑脚本”，而是“系统里长期存在的能力”。

### 运行时要点（领导追问“运行时到底谁干活”）
- 每次推理请求走该 provider，由 plugin 的实现执行。
- 重试/限流/超时/审计/观测都能在这一层统一收敛。

---

## Skill 路线的上限（一句话别讲长）
- Skill 最多让模型在会话里通过脚本去调用内部模型，是“会话级代理”，不是“系统级接入/治理”。
