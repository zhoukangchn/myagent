# OpenClaw：Plugin / Skill / Tool call（抓住“启动时”和“运行时”就不乱）

> 这份笔记的唯一目的：把概念讲到“可落地、可解释、不会混”。
> 我们只抓两个时间点：**启动时（startup）** 和 **运行时（runtime）**。

---

## 0) 三句结论（先给结论，再讲理由）
1. **Plugin = 能力 + 执行**：它不只是“启动时加载一下”，更重要的是 **运行时承接 tool call 干活**。
2. **Skill = 方法 + 流程**：它更像“说明书/SOP”，会被注入提示词，影响模型怎么选工具、怎么填参、怎么兜底。
3. **Tool call = 按下按钮**：模型在运行时发起结构化调用，系统把它路由到对应 plugin 的实现。

口诀版：
- Plugin 给“手和工具箱”
- Skill 给“说明书和操作步骤”
- Tool call 是“按按钮”

---

## 1) 启动时（Startup）：Plugin 在干什么？
启动时关心的是：**这套能力能不能被系统识别、能不能被配置、能不能被纳入治理**。

在启动/加载阶段，Plugin 主要做三类事：

### 1.1 被加载（框架把插件拉起来）
- Gateway 启动时会发现并加载插件（来源/优先级属于实现细节，这里不展开）。

### 1.2 准备运行环境（底座能力就位）
- 鉴权材料/凭证读取
- HTTP client、连接池
- 重试/超时/限流策略
- 日志与观测
- 需要的话：数据库/队列连接

> 这一步的关键词：**“准备好能跑”**。

### 1.3 注册能力（把“工具接口”挂到系统里）
- 注册 tools / commands / handlers 等，让 OpenClaw 知道“系统现在多了哪些能力入口”。

> 启动时一句话：**Plugin 把能力“装进系统”并准备好执行环境。**

---

## 2) 运行时（Runtime）：真正“干活”发生在哪里？
运行时关心的是：**一次具体调用怎么执行、是否稳定、能否观测与兜底**。

当用户问问题/触发任务时：

### 2.1 Skill 发挥作用（教模型怎么做）
Skill 会把流程知识塞进提示词：
- 先问什么信息
- 用哪个 tool
- 参数怎么填
- 失败怎么处理
- 输出格式是什么

### 2.2 模型发起 tool call（按下按钮）
模型根据 skill 的指导发出：
- tool name + 参数（结构化）

### 2.3 Plugin 执行 tool call（真正干活）
系统把 tool call 路由到 plugin 的实现，然后 plugin 去做真正的 I/O：
- 请求外部 API
- 读写数据库/队列
- 处理重试/超时/限流
- 返回结构化结果

> 运行时一句话：**Plugin 在 tool call 发生后执行；Skill 在 tool call 发生前“指导”。**

---

## 3) 把它们放在一起：一条调用链（最重要）
用户：**“帮我查一下上海明天会不会下雨？”**

1. 系统注入天气 skill（告诉模型：需要 city/date，用哪个 tool，怎么兜底）
2. 模型发起 tool call：`get_weather(city="上海", date="明天")`
3. 系统路由到天气 plugin 的 tool 实现
4. plugin 运行时请求天气 API → 返回结构化结果
5. 模型把结果组织成中文回答

---

## 4) 你会议里那个关键例子：内部模型接入为什么要 Plugin？
你之前那句其实可以讲得更硬：

### 4.1 用 Plugin 接入内部模型 = “系统级接入（Provider 方式）”
**启动时：**
- plugin 被加载
- 初始化内部模型调用所需的底座（鉴权/客户端/路由/观测）
- **注册内部模型 provider/auth**：让 OpenClaw 在“系统模型层”认识你们的内部模型，并能被选择/配置

**运行时：**
- 每一次推理请求走这个 provider，由 plugin（provider 实现）执行
- 统一处理：超时/重试/限流/日志/审计/降级

### 4.2 只用 Skill 调内部模型 = “会话级脚本代理”
- Skill 最多让模型在某个会话里 `exec` 跑脚本/发 HTTP
- 这不等价于系统接入：
  - 不能把模型接入变成系统稳定能力面
  - 很难统一治理（参数/返回/鉴权/审计容易散落在脚本里）

> 这段你可以用一句话收尾：
> **Plugin 把内部模型变成系统能力；Skill 只是教模型在某次对话里怎么“临时调用”。**

---

## 5) 给领导的“启动 vs 运行”最短总结（30 秒版）
- **启动时**：Plugin 负责“加载 + 准备底座 + 注册能力入口”（让系统具备这项能力）。
- **运行时**：Plugin 负责“承接调用并执行”（让每次调用可靠可控）；Skill 负责“指导模型如何调用”。
